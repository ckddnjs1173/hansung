# 한성자동차 파견인력 통합 관리프로그램 기획안

작성일: 2026-09-07
기획 기준: 기존 운영자료 48개 파일 분석 결과

## 1. 기획 결론

이 프로그램의 핵심은 여러 엑셀 파일을 웹 화면으로 옮기는 것이 아니다. 인력, 지점, 직무, 계약을 한 번 등록하면 근태, 연차, 대체근무, 월 청구, 퇴사 정산, 계약 문서가 같은 데이터를 사용하도록 만드는 것이 핵심이다.

권장 형태는 PC에서 주로 사용하고 휴대폰에서도 승인과 제출이 가능한 사내용 반응형 웹 프로그램이다. 초기 버전은 운영 담당자 2~5명이 사용하는 내부 시스템으로 시작하고, 이후 현장 책임자와 근로자용 제출 화면을 단계적으로 개방한다.

주요 목표는 다음과 같다.

- 재직자와 퇴사자를 별도 파일로 복사하지 않고 재직 상태와 이력으로 관리한다.
- 월마다 청구 엑셀을 새로 만들지 않고 마감 월을 선택해 자동 산출한다.
- 근무내역, 연차, 대체근무 기록이 청구 자료에 다시 입력되지 않게 한다.
- 지점명, 직무명, 책임자, 급여 기준을 코드화해 오기와 중복을 줄인다.
- 개별계약서, 근로계약서, 입사 안내문을 인력 정보에서 자동 생성한다.
- 개인정보와 급여 정보는 역할에 따라 필요한 사람만 열람하게 한다.
- 모든 변경 내역과 월 마감 이력을 남겨 사후 확인이 가능하게 한다.

## 3. 현재 업무 흐름과 불편 원인

### 3.1 현재 업무 흐름

1. 채용 담당자가 합격자 정보를 정리한다.
2. 운영 담당자가 근로자명부와 사용사업관리대장에 다시 입력한다.
3. 직무별 Word 파일을 골라 계약서와 입사 안내문을 작성한다.
4. 매월 근로자가 근무내역서를 작성하고 현장 결재를 받아 사진, 문자 또는 이메일로 제출한다.
5. 운영 담당자가 연장근로, 휴일근로, 연차, 결근, 인센티브를 청구 엑셀에 다시 입력한다.
6. 급여와 간접비, 수수료, 기타 비용을 계산해 월 청구서와 인보이스를 만든다.
7. 퇴사 시 재직자 자료를 퇴사자 자료로 옮기고 연차수당과 퇴직금을 별도 계산한다.
8. 휴가 대체인력이 필요한 경우 과거 근무이력과 전화번호를 보고 후보자를 찾는다.
9. 재고조사와 같은 단기 프로젝트는 별도 인원표와 견적표로 관리한다.

## 4. 사용자와 권한

### 4.1 사용자 역할

| 역할 | 주요 사용 기능 |
| --- | --- |
| 시스템 관리자 | 사용자 권한, 코드, 계산 규칙, 문서 템플릿, 전체 감사기록 관리 |
| 운영 매니저 | 인력과 배치 관리, 현장 이슈, 계약 생성, 대체인력 배정, 퇴사 처리 |
| 채용 담당자 | 후보자, 합격자, 입사 예정자, 제출서류와 온보딩 관리 |
| 급여·청구 담당자 | 근태 마감, 급여 기준, 인센티브, 퇴직 정산, 청구 확정과 파일 출력 |
| 현장 책임자 | 소속 지점 인력 확인, 근태·연차·대체근무 승인, 이슈 등록 |

### 4.2 권한 원칙

- 주민등록번호, 계좌, 주소, 연락처는 필드 단위로 권한을 나눈다.
- 급여와 청구 금액은 급여·청구 담당자와 승인권자만 본다.
- 현장 책임자는 자기 지점에 현재 배치된 인력만 본다.
- 근로자는 본인 정보와 본인 제출 건만 본다.
- 다운로드 파일에는 사용자, 일시, 조회 조건을 기록한다.
- 민감정보 조회, 수정, 다운로드, 마감 취소는 감사로그에 남긴다.

## 5. 정보 구조와 주요 메뉴

### 5.1 홈 대시보드

첫 화면은 오늘과 이번 마감에 필요한 일만 보여준다.

- 현재 재직 인원, 입사 예정, 퇴사 예정, 계약 만료 예정
- 이번 달 근무내역 미제출과 승인 대기
- 연차 잔액 부족 또는 발생 예정
- 대체근무 미배정 요청
- 월 청구 입력 누락, 계산 오류, 승인 상태
- 지점별 현재 인원과 정원 차이
- 최근 현장 이슈와 처리 기한
- 재고조사 등 진행 중인 단기 프로젝트

각 숫자를 누르면 해당 조건이 적용된 목록으로 바로 이동한다.

### 5.2 인력 관리

한 화면에서 현재 상태를 파악할 수 있는 인력 카드가 중심이다.

기본정보:

- 사번, 성명, 생년월일, 연락처, 이메일, 주소
- 긴급연락처, 계좌정보, 보험 관련 구분
- 채용 경로, 입사 예정일, 실제 입사일, 퇴사일과 사유
- 재직 상태: 후보, 합격, 입사 예정, 재직, 휴직, 퇴사
- 제출서류 체크리스트와 파일

하위 탭:

- 배치·계약 이력
- 근태·연차
- 급여 기준·인센티브
- 생성 문서와 서명 상태
- 교육 이수
- 현장 이슈와 상담 기록
- 변경 이력

재직자와 퇴사자는 별도 데이터가 아니라 상태 필터로 구분한다.

### 5.3 지점·부서·책임자 관리

- 구분: 본사, 신차 전시장, 서비스센터, 중고차 전시장, BDC 등
- 공식 지점명, 약어, 과거 명칭, 주소, 운영 상태
- 현장 책임자와 업무지휘명령자의 유효기간
- 지점별 운영 직무와 정원
- 근무시간, 휴게시간, 토요일·공휴일 운영 규칙
- 현장별 특이사항과 매뉴얼

책임자는 단순 덮어쓰기가 아니라 시작일과 종료일을 가진 이력으로 관리한다. 특정 날짜의 계약서나 관리대장을 다시 출력할 때 당시 책임자가 표시되어야 한다.

### 5.4 직무·급여 기준 관리

- 표준 직무명, 표시명, 직업분류기호, 허용 사업장 유형
- 주중·주말·스케줄·야간 등 근무형태
- 기본급, 식대, 고정연장, 휴가비, 기타 고정수당
- 월 기준시간과 일·시간 단가
- 복리후생비, 사고충당금, 관리비, 수수료 기준
- 적용 가능한 인센티브 종류
- 업무내용, 자격요건, 교육과정, 복장과 입사 안내
- 시행일과 종료일, 승인자, 변경 사유

같은 직무라도 지점이나 근무형태에 따라 다른 기준을 둘 수 있다. 변경 시 기존 월의 계산값은 유지하고 새 시행일 이후에만 새 기준을 적용한다.

### 5.5 배치·계약 관리

배치는 `누가, 언제부터 언제까지, 어느 지점에서, 어떤 직무와 근무형태로 일했는가`를 나타낸다.

- 근로자, 지점, 직무, 근무형태
- 배치 시작일과 종료일
- 계약 기간과 연장 회차
- 급여 기준 버전
- 업무지휘명령자와 관리책임자
- 정원 반영 여부와 대체근무 여부
- 계약 상태: 작성 전, 검토, 서명 요청, 체결, 종료

배치 정보를 저장하면 개별계약서, 근로계약서, 개인정보 동의서, 입사 안내문에 필요한 값이 자동으로 준비된다.

### 5.6 근태·근무내역

입력 화면은 70열짜리 청구표가 아니라 날짜별 근무 기록으로 구성한다.

- 근무일, 예정 근무시간, 실제 시작·종료
- 연장, 야간, 휴일, 주말·공휴일 근로시간
- 지각, 조퇴, 결근, 휴직, 무급 처리
- 식대와 영수증
- 비고와 증빙파일
- 제출자, 제출일, 현장 승인자, 승인일

근로자는 휴대폰에서 날짜별 예외만 입력할 수 있어야 한다. 정상 근무일은 예정 스케줄을 기본값으로 두고, 연장·휴일·결근 등 변경 사항만 제출하도록 한다.

마감 주기는 급여 월과 근무내역 수집 기간을 별도로 설정한다. 현재 운영처럼 21일부터 다음 달 20일까지 수집하는 경우도 지원하고, 청구 월 기준으로 자동 귀속시킨다.

### 5.7 연차·휴가 관리

- 연차 정책: 주중, 주말, 단시간 등 근무형태별 정책
- 발생 내역, 조정 내역, 사용 내역, 소멸·정산 내역
- 일 또는 시간 단위 관리
- 신청, 현장 승인, 운영 승인, 취소
- 경조휴가 종류와 유급일수
- 입사 1년 미만, 계약 연장, 휴직, 무급월 예외 처리
- 퇴사일 기준 잔여연차와 미사용수당 계산

달력의 칸에 날짜 문자열을 적는 방식은 사용하지 않는다. 모든 휴가는 한 건의 신청 레코드로 저장하고 잔액은 원장 합계로 계산한다.

### 5.8 대체근무 관리

- 지점에서 필요한 날짜, 시간, 직무와 사유를 요청
- 과거 경험 지점, SVC/SR 경험, 최근 근무일, 누적 횟수로 후보 추천
- 거리, 가능 일정, 최근 평가, 차단 여부를 반영한 후보 정렬
- 전화·문자 연락 상태: 미연락, 연락 중, 가능, 불가, 확정
- 배정 확정 시 근무일정과 일급/시급 기준 자동 생성
- 근무 완료 후 근무이력, 지급·청구, 평가 자동 반영
- 같은 전화번호에 다른 이름이 있거나 중복 후보가 있으면 병합 검토 알림

### 5.9 월 청구·급여 산출

월 마감은 다음 단계로 진행한다.

1. 마감 회차 생성
2. 해당 월 배치 인원 자동 불러오기
3. 근태, 연차, 입퇴사, 휴직, 대체근무 자동 집계
4. 인센티브와 일회성 비용 입력 또는 일괄 업로드
5. 직접비, 간접비, 복리후생비, 사고충당금, 수수료 계산
6. 오류 점검
7. 담당자 검토와 승인
8. 마감 잠금
9. 청구 상세, 인보이스, 퇴사자 연차·퇴직금 내역 출력

화면은 세 부분으로 나눈다.

- 입력 필요: 근무일수, 예외근태, 인센티브, 일회성 조정
- 자동 계산: 기본급 일할, 수당, 보험·부담금, 수수료, VAT
- 결과: 개인별 공급가액과 전체 청구 합계

사용자는 결과 금액에서 계산 근거를 펼쳐볼 수 있어야 한다. 직접 값을 덮어써야 할 경우에는 조정 사유와 승인자를 필수로 남긴다.

### 5.10 퇴사·정산

- 퇴사 예정 등록과 인수인계 체크리스트
- 최종 근무일, 퇴사일, 퇴사 사유
- 잔여연차와 미사용연차수당
- 최근 임금 기간과 평균임금·통상임금 비교
- 퇴직금 계산 근거
- 비밀유지서약서 등 퇴사 문서
- 장비·자료 반납 확인
- 마지막 청구 월 반영
- 퇴사 완료 후 개인정보 보유기간과 파기 예정 관리

퇴사 완료는 인력 레코드를 삭제하지 않고 상태를 변경하는 방식으로 처리한다.

### 5.11 문서·온보딩·교육

- 개별계약서와 근로계약서 자동 생성
- 개인정보 동의서, 비밀유지서약서, 입사 안내문 생성
- 직무·근무형태·지점에 따른 조건 문구 자동 선택
- 템플릿 버전과 사용 이력 보존
- 전자서명 또는 서명본 업로드
- 입사 전 제출서류 체크리스트
- 직무별 교육과정, 교육시간, 이수일, 담당자
- 현장 매뉴얼 열람 확인

문서 템플릿 안에 계정 비밀번호를 보관하지 않는다. 업무 시스템 접근정보는 별도 계정 발급 절차로 관리한다.

### 5.12 단기 프로젝트·재고조사

재고조사는 상시 파견인력과 다른 흐름을 가지므로 프로젝트 기능으로 분리한다.

- 프로젝트명, 기간, 지점, 일자별 필요 인원과 근무시간
- 지점 담당자와 연락처
- 후보자 모집·배정·출근 확인
- 일급과 간접비·관리비·수수료 기준
- 일별·지점별 인원 충족 현황
- 실제 투입 인원과 예상 대비 차이
- 견적서와 최종 청구 자료 출력

프로젝트가 끝나도 투입자의 근무이력은 대체인력 풀과 연결할 수 있다.

### 5.13 보고서·감사

- 기준일 현재 재직자 명부
- 퇴사자 명부와 기간별 퇴사율
- 지점·직무별 인원과 정원 차이
- 계약 만료 예정과 2차 연장 현황
- 업무지휘명령자와 관리책임자 이력
- 연차 발생·사용·잔액·정산
- 대체근무 요청과 충원율
- 채용 소요기간, 후보 이탈 사유, 입사 후 유지율
- 월별 급여·청구 증감과 조정 내역
- 단기 프로젝트 투입과 비용
- 모든 중요 필드 변경과 파일 다운로드 이력

## 7. 계산 규칙 설계

기존 엑셀의 수식을 그대로 코드에 박아 넣으면 다음 요율 변경 때 다시 불편해진다. 계산 규칙은 관리자 화면에서 버전으로 관리하고, 마감 시 사용한 버전을 결과에 함께 저장한다.

필수 규칙:

- 월급·시급·일급 지급형태
- 월 기준시간과 소정근로일
- 입사·퇴사·휴직 일할 계산
- 고정연장, 실제 연장, 야간, 휴일, 주말·공휴일 수당
- 주말 근로자의 주휴와 공휴일 포괄 항목
- 식대와 비과세 한도
- 국민연금, 건강보험, 장기요양, 산재, 고용보험
- 임금채권, 석면피해구제, 장애인고용분담금, 사업소세
- 복리후생비, 사고충당금, 관리비, 이익금·수수료
- 직무별 인센티브와 일회성 조정
- 미사용연차수당과 퇴직금
- 항목별 원 단위 절사·반올림·올림
- VAT 계산

모든 규칙에는 `이름`, `적용 대상`, `계산식`, `시행일`, `종료일`, `근거 메모`, `승인자`가 있어야 한다. 법정 요율과 계약 해석은 실제 운영 적용 전에 노무·회계 담당자가 검증해야 한다.

## 8. 사용성 원칙

- 목록보다 해야 할 일을 먼저 보여준다.
- 정상값은 자동으로 채우고 예외만 입력한다.
- 한 화면에서 한 가지 업무를 끝낼 수 있게 한다.
- 지점·직무·상태는 직접 타이핑하지 않고 검색 선택한다.
- 저장 전에 즉시 오류를 표시하고 해결 방법을 함께 보여준다.
- 금액은 결과만 보여주지 않고 계산 근거를 펼쳐볼 수 있게 한다.
- 자주 쓰는 조건은 개인별 필터로 저장한다.
- 엑셀 내보내기는 유지하되 시스템 데이터의 복사본으로 취급한다.
- 모바일은 근태 제출, 휴가 신청, 승인, 대체근무 응답에 집중한다.
- 삭제 대신 종료·취소 상태를 사용해 이력을 보존한다.

## 9. 주요 자동 알림

- 입사 전 필수서류 미제출
- 계약 시작 전 미서명, 만료 60·30·7일 전
- 근무내역 제출 마감 전과 미제출
- 연차 승인 대기와 잔액 부족
- 대체근무 요청 미배정
- 월 마감 필수값 누락과 전월 대비 큰 금액 변동
- 퇴사 정산 미완료
- 책임자 공석 또는 유효기간 종료
- 교육 미이수
- 개인정보 보유기간 종료와 파기 검토

알림은 프로그램 안 알림을 기본으로 하고, 이메일·문자·메신저 연동은 2단계에서 선택한다.

## 10. 기존 데이터 이관 계획

### 10.1 이관 순서

1. 지점과 약어를 표준화하고 과거 별칭을 매핑한다.
2. 직무명과 직업분류기호를 표준화한다.
3. 재직자·퇴사자 파일을 합쳐 근로자 후보 레코드를 만든다.
4. 사번, 연락처, 성명+생년월일 조합으로 중복 후보를 탐지한다.
5. 계약 문자열을 계약 회차 레코드로 분리한다.
6. 책임자 목록을 유효기간 이력으로 이관한다.
7. 연차대장의 발생·사용·잔액을 기준일 스냅샷과 사용이력으로 변환한다.
8. 대체근무 DB와 근무이력을 인력 프로필과 배정 이력으로 분리한다.
9. 최근 1~3개월 청구 자료를 테스트 이관해 새 계산 결과와 대조한다.
10. 차이가 승인 기준 안에 들어오면 운영 전환한다.

### 10.2 이관 시 자동 점검

- 존재하지 않는 날짜와 시작일보다 빠른 종료일
- 같은 사번의 여러 사람, 같은 연락처의 여러 이름
- 지점명·직무명 미매핑
- 계약기간 중복과 공백
- 재직 상태와 퇴사일 충돌
- 급여 기준이 없는 배치
- 연차 발생·사용·잔액 불일치
- 월 청구 대상과 재직자 명부 불일치
- 비정상적으로 큰 금액과 전월 대비 급증감

원본 값은 수정하지 않고 `원본값`, `변환값`, `검토상태`를 함께 보관한다.

## 11. 단계별 개발 범위

### 1단계: 운영 핵심 MVP

목표는 월 마감과 인력 관리의 중복 입력을 제거하는 것이다.

- 로그인과 역할별 권한
- 인력 통합 마스터
- 지점·직무·책임자·급여 기준 마스터
- 배치와 계약기간 관리
- 재직·입퇴사·계약만료 현황
- 근태 예외 입력과 승인
- 연차 원장과 신청·승인
- 월 청구 계산, 검증, 잠금
- 인보이스와 청구 상세 Excel/PDF 출력
- 기존 Excel 일괄 가져오기
- 변경 이력과 다운로드 로그

MVP 완료 기준:

- 인력 한 명을 등록한 뒤 다른 메뉴에서 재입력하지 않는다.
- 최근 월 청구 자료를 동일 조건으로 재현하고 차이를 설명할 수 있다.
- 재직자·퇴사자·사용사업관리대장을 기준일로 출력할 수 있다.
- 연차 신청이 승인되면 잔액과 월 청구에 자동 반영된다.
- 마감 후 데이터가 임의로 바뀌지 않는다.

### 2단계: 현장 협업과 문서 자동화

- 근로자 모바일 근무내역 제출
- 현장 책임자 승인
- 대체근무 요청, 후보 추천, 배정
- 계약서·동의서·입사안내 자동 생성
- 전자서명 또는 서명본 관리
- 온보딩 서류와 교육 이수
- 계약만료와 제출마감 자동 알림
- 현장 이슈와 상담 기록

### 3단계: 프로젝트와 경영 보고

- 재고조사 등 단기 프로젝트 운영
- 채용 파이프라인과 인재풀
- 지점별 정원·충원율·이탈률
- 비용 추이와 전월 비교
- 이메일·문자·메신저 연동
- 필요 시 회계·급여 시스템 연동

## 12. 권장 기술 구성

초기 내부 웹 프로그램 기준의 권장안이다.

- 화면·서버: Next.js + TypeScript
- 데이터베이스: PostgreSQL
- 데이터 접근: Prisma
- 인증: 사내 계정 또는 이메일 기반 로그인과 다중 역할 권한
- 파일: 계약서·증빙용 비공개 객체 저장소
- 문서 생성: DOCX 템플릿 병합과 PDF 변환
- Excel: 기존 양식 가져오기와 결과 내보내기
- 배포: 사내망 또는 접근제어가 가능한 클라우드
- 백업: 일일 자동 백업과 월 마감 스냅샷

개인 PC에만 설치하는 단일 사용자 프로그램보다 웹 방식이 데이터 중복, 승인, 백업, 권한 관리에 유리하다. 단, 사용자가 한 명이고 외부 접근이 전혀 필요 없다면 로컬 실행형도 대안으로 검토할 수 있다.

## 13. 화면 우선순위

실제 설계와 개발은 다음 순서가 효율적이다.

1. 홈 대시보드
2. 인력 목록과 인력 상세
3. 지점·직무·급여 기준
4. 배치·계약
5. 근태·연차
6. 월 청구 마감
7. 대체근무
8. 문서·온보딩
9. 퇴사 정산
10. 단기 프로젝트·재고조사
11. 보고서·감사·설정

## 14. 구현 전에 확정할 운영 정책

다음 항목은 기획 방향을 바꾸기보다 계산과 권한의 정확도를 위해 확정이 필요하다.

- 실제 사용자 수와 역할별 담당자
- 근로자가 직접 로그인할지, 담당자가 대신 입력할지
- 현장 책임자가 프로그램 안에서 승인할 수 있는지
- 근무내역 수집기간과 급여·청구 귀속 기준
- 연차 발생과 미사용수당의 직무·근무형태별 정책
- 퇴직금 계산과 최종 승인 담당자
- 보험·부담금·수수료의 최신 요율과 시행일
- 전자서명 서비스 사용 여부
- 주민등록번호와 계좌정보의 실제 저장 필요 범위
- 기존 자료를 몇 년치까지 이관할지
- 사내망, 외부 클라우드, 로컬 설치 중 배포 방식
- 한성자동차 현장 책임자와 근로자에게 계정을 제공할지

## 15. 다음 작업 제안

다음 단계에서는 이 기획을 기준으로 `MVP 화면설계 → 데이터베이스 설계 → 기존 자료 이관 규칙 → 월 청구 계산 검증 → 구현` 순서로 진행한다.

첫 구현 범위는 인력, 지점·직무, 배치·계약, 근태·연차, 월 청구의 다섯 흐름으로 제한하는 것이 좋다. 이 다섯 기능이 안정되면 대체근무, 문서 자동화, 재고조사 기능을 붙여도 데이터 구조를 다시 만들 필요가 없다.
